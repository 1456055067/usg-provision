# Fuzz targets

This directory is a separate Cargo workspace for
[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) targets. It links
libFuzzer (C++) through `libfuzzer-sys`, which is allowed only here and is
never built into, linked with, or shipped as part of any product artifact
([decision 0002](../docs/decisions/0002-fuzz-harness-native-code.md)). The
root workspace gates do not cover `fuzz/`.

## Prerequisites

- The nightly toolchain pinned in `fuzz/rust-toolchain.toml` (rustup picks it
  up automatically inside this directory).
- `cargo install --locked cargo-fuzz@0.13.2`

## Running

```sh
cd fuzz
cargo fuzz build
cargo fuzz run <target> -- -max_total_time=60
```

## Rules

- **Smoke rule:** every target touched by a change runs for at least 60
  seconds with no crash before the change is accepted. Milestones may set
  longer runs (for example, 10 minutes per parser in M1 and M2).
- **Naming:** `<crate>_<input>`, for example `dhcp_packet`, `tftp_packet`,
  `wim_header`.
- **Corpus:** `fuzz/corpus/<target>/`. Crash artifacts (`fuzz/artifacts/`)
  and coverage output (`fuzz/coverage/`) are not committed.
- **Seed origin:** every seed is generated by our own code, hand-built from
  an open-standard description, or taken from a published open-standard
  test vector. Never seed from packet captures, logs, images, or any other
  file from a deployment of the vendor product. Record each seed's origin
  (generator and arguments, or standard and section) in
  `fuzz/corpus/<target>/SOURCE.md`. Seeds with no recorded origin are not
  committed. The same rule covers test fixtures in crates
  ([CONTRIBUTING.md](../CONTRIBUTING.md#test-data-and-fuzz-corpora)).
- Every network or file parser gets a target (CLAUDE.md, Engineering Rules).

The `noop` target only proves the harness builds; it is deleted when
`dhcp_packet` lands (M1).
