# Seed origin: `efi_load_option`

Every seed here is generated by our own code: `usgp_disk::uefi`
encoders (`LoadOption::windows_boot_manager` for the ESP of a 64 GB
layout from `WindowsUefiLayout::compute`, `LoadOption::encode`,
`encode_boot_order`) and variable names written in the generator from
UEFI 2.10 §3.3 (`specs/standards/uefi-boot-manager.md` §10.3). None comes
from a firmware variable store, an NVRAM dump, a disk or any deployment of
another product (fuzz/README.md, seed origin rule).

Octet 0 selects the path (see `fuzz_targets/efi_load_option.rs`).

Regenerate (from `fuzz/`; function `efi_seeds`):

```sh
cargo run --example gen_seeds_m3 -- corpus
```

| Seed | Selector | Content |
|------|----------|---------|
| `wu14-efi-windows-boot-manager.bin` | 0 | our Windows Boot Manager option for the layout's ESP |
| `wu14-efi-optional-data-multi-path.bin` | 0 | the same with a hardware node first, a second path of two instances, and 8 octets of optional data |
| `wu14-efi-limits-prefix.bin` | 0 | five limit octets (`ff ff 40 ff ff`) then the first option |
| `wu14-efi-boot-order.bin` | 1 | `BootOrder` 3, 1, 0, 2, 1 |
| `wu14-efi-boot-order-odd.bin` | 1 | three octets (odd length; refused) |
| `wu14-efi-name-boot0001.bin` | 2 | `Boot0001` |
| `wu14-efi-name-bootorder.bin` | 2 | `BootOrder` |
| `wu14-efi-name-lower.bin` | 2 | `Boot00a1` (lower-case digit; refused) |
| `wu14-efi-name-pk.bin` | 2 | `PK` (a Secure Boot variable; refused) |
| `wu14-efi-esp.bin` | 3 | the layout ESP's number, start, size and GUID, then selector octet 3 |
