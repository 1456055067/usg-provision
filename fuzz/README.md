# Fuzz targets

This directory is a separate Cargo workspace for
[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) targets. It links
libFuzzer (C++) through `libfuzzer-sys`, which is allowed only here and is
never built into, linked with, or shipped as part of any product artifact
([decision 0002](../docs/decisions/0002-fuzz-harness-native-code.md)). The
root workspace gates do not cover `fuzz/`.

## Prerequisites

- The nightly toolchain pinned in `fuzz/rust-toolchain.toml` (rustup picks it
  up automatically inside this directory).
- `cargo install --locked cargo-fuzz@0.13.2`

## Running

Always pass a scratch working corpus first and the checked-in seeds
second, so inputs found by the fuzzer (which have no recorded origin) never
land in `fuzz/corpus/`:

```sh
cd fuzz
cargo fuzz build
mkdir -p /tmp/work/<target>
cargo fuzz run <target> /tmp/work/<target> corpus/<target> -- -max_total_time=60
```

## Rules

- **Smoke rule:** every target touched by a change runs for at least 60
  seconds with no crash before the change is accepted. Milestones may set
  longer runs (for example, 10 minutes per parser in M1 and M2).
- **Naming:** `<crate>_<input>`, for example `dhcp_packet`, `tftp_packet`,
  `wim_header`.
- **Corpus:** `fuzz/corpus/<target>/`. Crash artifacts (`fuzz/artifacts/`)
  and coverage output (`fuzz/coverage/`) are not committed.
- **Seed origin:** every seed is generated by our own code, hand-built from
  an open-standard description, or taken from a published open-standard
  test vector. Never seed from packet captures, logs, images, or any other
  file from a deployment of the vendor product. Record each seed's origin
  (generator and arguments, or standard and section) in
  `fuzz/corpus/<target>/SOURCE.md`. Seeds with no recorded origin are not
  committed. The same rule covers test fixtures in crates
  ([CONTRIBUTING.md](../CONTRIBUTING.md#test-data-and-fuzz-corpora)).
- Every network or file parser gets a target (CLAUDE.md, Engineering Rules).

## Targets

| Target | Input | Invariants |
|--------|-------|------------|
| `dhcp_packet` | one DHCP/PXE message (`usgp-dhcp`) | no panic; every reply re-parses as a BOOTREPLY with `yiaddr` 0, none of options 1, 3, 51, 58, 59, xid and chaddr echoed, within the size limit, option 82 echoed byte-for-byte or absent |
| `tftp_packet` | selector octet, then one packet or a transfer script (`usgp-tftp`) | no panic; parse/encode round trip; DATA blocks strictly increasing and never past the final block; no `Send` on a duplicate ACK; any opcode-5 datagram of 4 or more octets from the client TID ends the transfer (BOOT-005); retries within the cap; `Done` is final; DATA payload equals the file |
| `wim_header` | the first bytes of a WIM file (`usgp-image` `parse_header`, `check_header`) | no panic; listed reason code on every refusal; accepted only with signature and `cbSize` 208; every field equals an independent LE read and resource headers re-encode; `check_header` keeps image count, boot index, part and chunk-size rules and agrees with `classify_flags`; `check_within` never accepts a range outside the file |
| `wim_xml` | WIM XML resource, UTF-16LE + BOM; also as UTF-8 text (`parse_xml`, `parse_xml_str`) | no panic; listed reason code; `parse_xml` = decode + parse, accepted bytes re-encode; accepted result within every limit, indexes ≥ 1 and increasing, `NAME`/`DESCRIPTION` match their leaves; tighter limits never accept more |
| `wim_lookup` | a lookup table (`parse_table`) for both compressions, three file lengths, two image limits | no panic; result and refusal equal an independent `check_entry` walk; entries re-encode; acceptance monotone in file length |
| `wim_check` | a whole WIM file in memory (`check_wim` with the FIPS provider, `check_pe`) | no panic; listed reason code and operator text on every refusal; no `wim_check_stalled` unless progress stops it, and a stop at the first report never accepts; accepted: 1 to limit images, editions 1..N, boot index ≤ N, `check_pe` index in 1..N or `pe_no_usable_image` |
| `xpress_chunk` | selector octet; decode (expected length + chunk) or round trip (`XpressDecoder`, `decode_xpress_chunk`, test encoder) | no panic; never writes past the expected length (sentinel); exact length (n - 1 and n + 1 fail); reused decoder equals a fresh one; own encoder output round-trips |
| `api_json` | selector octet, then a JSON body, envelope, manifest payload or `If-Match` value (`usgp-proto`) | no panic; `body_too_large` exactly over the cap; parser detail ≤ 200 chars; requests, envelopes and manifests round-trip; validated requests are stable; `If-Match` accepted only in the canonical `"r<n>"` form |
| `gpt_readback` | selector, LBA count, head and tail bytes of an in-memory disk (`usgp-disk` `parse_gpt`, `mbr::read_lba0`) | no panic; never writes; deterministic; accepted view within the layout and entry rules (REQ-DISK-009) with a protective MBR; limits monotone, `Limit` one entry below the table; a fixed-geometry table rebuilds as a `GptPlan` that matches and reads back equal; legacy records in slot order |
| `efi_load_option` | selector; `Boot####` value, `BootOrder` value, variable name or ESP fields (`usgp-disk` `uefi`) | no panic; accepted option ends each path in one End node within limits, re-encodes to its exact bytes when printable ASCII (OPEN-UBM-2); limits monotone; `put_first` and `free_option_number` equal reference models; only `BootOrder` and `Boot####` named; our Windows option round-trips and `points_to` only its ESP |
| `wim_metadata` | a decoded metadata resource (`usgp-image` `parse_metadata`, 1 MiB / 10,000-entry limits) | no panic; listed reason code; accepted tree satisfies the M-01 to M-23 shape rules (parents, depth, names, path length, attributes, security index, kinds, hard-link groups); counts; limits monotone, one entry or one level less refused with `wim_meta_limit_exceeded` |
| `wim_apply_plan` | a whole WIM file, or a selector (image index, root, tamper offset) and file, or the re-base rule's inputs (`usgp-image` `verify_pass`, `apply`, `MemorySink`, `wim::reparse::prepare`) | no panic; listed reason code; verify and apply agree (same refusal, or same preview, bytes within it, one path per entry); a flipped octet is never accepted and nothing is written (SI-7); reparse buffers well framed; re-base rule equals a reference model of decision 0022 (copy, re-base onto the root in DISM's layout, refuse), output well formed, idempotent onto a drive root |
| `tftp_window` | a windowed-transfer script: file length, window, wrap mode, RRQ, ops (`usgp-tftp` `admit_read_with`) | no panic; admission rules; DATA wire numbers `wire(index)` inside the window with no gap and the file's bytes; in flight at most the window (64); `acked_index` monotone; no `Send` on an ACK that does not advance; `Wait` before the deadline; retries capped; `wraps()` agrees; `Completed` only after the final ACK with the whole file reassembled |
| `tftp_name` | selector; a request name, or NUL-separated published names (`usgp-tftp` `normalize_request_name`, `case_insensitive_collision`) | no panic; equals a reference model of the documented steps and refusal kinds; accepted names pass the allow-list, have no `.`/`..` component, are a fixed point and match case-insensitively; collisions reported exactly |
| `device_session_msgs` | selector; a device session request or response body, or a text value (`usgp-proto` `device`, `progress`) | no panic; `body_too_large` exactly over the cap; bodies round-trip; a refused code or token is never echoed, never in `Debug`; MAC, code, display code, token, nonce, disk token and GUID text forms follow reference models and round-trip |
| `job_plan` | selector; a plan payload, or a mode and a confirm response (`usgp-proto` `JobPlanV1`, `VerifiedJobPlan::verify`) | no panic; accepted payload canonical and round-trips; verify before parse (a refusing plan verifier is always the signature refusal and the content is never checked); checks 1 to 6 equal a reference model; an accepted plan carries the expected bindings and the content manifest's SHA-256; every refusal is an integrity failure with a plan reason code |
| `boot_manifest` | boot manifest TOML with `[pe_kit]` (`usgp-proto` `BootManifest::from_toml`) | no panic; accepted manifest validates and round-trips through `to_toml`; `get` exact; kit within the font limit with distinct roles; `assess` equals a reference model |
| `pe_coff` | a boot program's file head (`usgp-proto` `pe_coff::check_uefi_x64_application`) | no panic; equals a reference model of the documented field checks; independent of bytes outside them |
| `agent_config` | selector; `agent.toml` text or a server URL (`usgp-proto` `AgentConfigFile::from_toml`, `parse_server_url`) | no panic; refusals name a key; accepted file has settings in range with a valid host and round-trips; an accepted URL rebuilt from host and port parses back equal |
| `relay_boot_policy` | a script over lists the target signs at start-up, flipped and raw envelopes (`usgp-relay` `BootPolicyFeed::apply_bytes`) | no panic; fail closed before a list; every result equals a reference model of the documented check order (envelope, signature, payload, service, rollback, reuse); the gate holds exactly the model's list |
| `relay_feed_url` | `[server_feed] url` text (`usgp-relay` `FeedUrl::parse`) | no panic; equals a reference model of `https://host[:port][/]`; `authority()` parses back; the agent's `parse_server_url` accepts it with the same host and port |
| `unattend_template` | answer-file template bytes (`usgp-wincfg` `Template::parse`, `references`, `lint`, `render`) | no panic; `TooLarge` exactly over the limit; tighter limits never accept more; references sorted and unique; unknown references reported by lint; render with no values fails on the first reference; render with valid values never fails its self-check, is deterministic and (without the `{{{{` escape) re-parses with no references left |
| `zip_archive` | a ZIP file in memory, plain and driver mode, default and tight limits (`usgp-wincfg` `validate_archive_mode`, `extract_archive_mode`) | no panic; listed reason code; validate and extract agree; the sink sees only safe relative paths, parents first, no folded duplicate, exactly the declared bytes, `expanded` in total; INF list sorted, unique, `.inf` only; modes differ only by `no_inf_packages`; tight limits never accept more |
| `cab_archive` | a cabinet in memory (octets 0 to 3 forced to `MSCF`), as `zip_archive` | as `zip_archive`; accepted input is a cabinet |
| `inflate_diff` | selector; a raw DEFLATE stream, or a level and content (`usgp-wincfg` `inflate_slice` against `miniz_oxide`) | no panic; we accept exactly when the reference finishes within the 1 MiB budget having consumed all input, with the same output; budget and trailing-data refusals agree with the reference; reference-encoded content round-trips at every level |
| `inf_version` | one INF's text, placed as `pkg/x.inf` in a test ZIP with two catalogs (the archive INF scan) | no panic; plain mode always accepts; driver mode accepts exactly when the INF is listed; a listed INF decodes and holds `version`, `signature`, `catalogfile` and a known signature; fewer catalogs never list more; UTF-16LE form decides the same |
| `dism_driver_table` | list-format driver listing, lossy UTF-8 (`usgp-wincfg` `dism::parse_driver_table`) | no panic; `TooLarge` exactly over the cap; rows within limits, trimmed, required fields non-empty, no more than `Published Name` lines; rows written back re-parse equal; CRLF equals LF |
| `postsetup_msgs` | selector; resume, escrow, v2 progress or failure body, or `job.json` (`usgp-proto` `resume`, `escrow`, `progress`, `postsetup`) | no panic; `body_too_large` exactly over the cap; detail at most 200 chars; bodies round-trip; resumed token never in `Debug`; escrow lengths and point form; confirm code exactly on `set` false; v2 progress rules (schema, seq, bytes, step 9 success, restart flag, failure step); `job.json` validates, round-trips, holds a v2 plan envelope |
| `agent_package_manifest` | `agent.json` (`usgp-proto` `AgentPackageManifestV1::from_json`) | no panic; `TooLarge` exactly over the cap; accepted manifest within its rules (installer kind, arguments, exit codes, timeout) and round-trips |
| `content_manifest_v2` | a v2 content manifest payload (`usgp-proto` `ContentManifestV2::from_payload`, `open`) | no panic; `TooLarge` exactly over the cap; chunk count, lengths and kind rules for INF lists; payload canonical and stable; verify before parse (a refusing verifier always refuses the envelope); `open` agrees with `from_payload` and the key-id check |

## M1 run length

Milestone M1 (exit criterion 3) runs each target for 10 minutes with no
crash. Use a scratch working corpus first so that inputs found by the
fuzzer (which have no recorded origin) do not land in `fuzz/corpus/`:

```sh
cd fuzz
cargo fuzz build
mkdir -p /tmp/work/dhcp_packet /tmp/work/tftp_packet
cargo fuzz run dhcp_packet /tmp/work/dhcp_packet corpus/dhcp_packet -- -max_total_time=600 -max_len=1600
cargo fuzz run tftp_packet /tmp/work/tftp_packet corpus/tftp_packet -- -max_total_time=600 -max_len=4096
```

## M2 run length

Milestone M2 (plan WU-9, §10; exit criterion 2) runs `wim_header`,
`wim_xml` and `xpress_chunk` for 10 minutes each and `wim_lookup`,
`wim_check` and `api_json` for 60 seconds, all with no crash, OOM or
timeout:

```sh
cd fuzz
cargo fuzz build
for t in wim_header wim_xml xpress_chunk wim_lookup wim_check api_json; do mkdir -p /tmp/work/$t; done
L='-rss_limit_mb=2048 -timeout=10 -print_final_stats=1'
cargo fuzz run wim_header   /tmp/work/wim_header   corpus/wim_header   -- -max_total_time=600 -max_len=1024   $L
cargo fuzz run wim_xml      /tmp/work/wim_xml      corpus/wim_xml      -- -max_total_time=600 -max_len=16384  $L
cargo fuzz run xpress_chunk /tmp/work/xpress_chunk corpus/xpress_chunk -- -max_total_time=600 -max_len=70000  $L
cargo fuzz run wim_lookup   /tmp/work/wim_lookup   corpus/wim_lookup   -- -max_total_time=60  -max_len=4096   $L
cargo fuzz run wim_check    /tmp/work/wim_check    corpus/wim_check    -- -max_total_time=60  -max_len=262144 $L
cargo fuzz run api_json     /tmp/work/api_json     corpus/api_json     -- -max_total_time=60  -max_len=70000  $L
```

The WIM and XPRESS targets link the AWS-LC crypto module through
`usgp-image` and `usgp-crypto` (decision 0001 and its Amendment 1, the
same tree as the main workspace); `wim_check` uses it for the WIM format
SHA-1. Besides that, the only native code in the fuzz workspace is
libFuzzer (decision 0002). No shipped crate changes for fuzzing.

Seeds are regenerated with the commands in each `corpus/<target>/SOURCE.md`.

## M3 run length

Milestone M3 (plan WU-14) adds the thirteen targets above. Each runs for
60 seconds in the `fuzz-smoke` job, with no crash, OOM or timeout (the
M1 and M2 targets keep their lengths). The M3 plan's test section asks
for 10 minutes per WU-14 target; the orchestrator set 60 s for this
change, and the CI matrix entry is where the length is raised.

```sh
cd fuzz
cargo fuzz build
L='-rss_limit_mb=2048 -timeout=10 -print_final_stats=1'
for e in gpt_readback:65536 efi_load_option:8192 wim_metadata:65536 \
  wim_apply_plan:65536 tftp_window:1024 tftp_name:512 \
  device_session_msgs:16384 job_plan:16384 boot_manifest:16384 \
  pe_coff:4096 agent_config:4096 relay_boot_policy:256 relay_feed_url:1024; do
  t="${e%%:*}"; mkdir -p "/tmp/work/$t"
  cargo fuzz run "$t" "/tmp/work/$t" "corpus/$t" -- -max_total_time=60 -max_len="${e#*:}" $L
done
```

`relay_boot_policy` signs its lists once per process with a key it
generates and builds its (unused) TLS client from the `usgp-crypto` test
PKI (feature `test-pki`, enabled in this workspace only); it opens no
socket and writes no file. `job_plan` uses test-double signature
verifiers: the ECDSA check itself is `usgp-crypto`'s and is tested there.

M3 seeds are written by `examples/gen_seeds_m3.rs`
(`cargo run --example gen_seeds_m3 -- corpus`); `wim_metadata` and
`wim_apply_plan` also take the `usgp-image` example's seeds (see their
`SOURCE.md`).

## M4 run length

Milestone M4 (plan WU-12) adds the nine targets above. The archive and
inflate parsers (`zip_archive`, `cab_archive`, `inflate_diff`,
`inf_version`) and `unattend_template` run for 600 seconds in the
`fuzz-smoke` job, the others for 60 seconds, all with no crash, OOM or
timeout.

```sh
cd fuzz
cargo fuzz build
L='-rss_limit_mb=2048 -timeout=10 -print_final_stats=1'
for e in unattend_template:65536 zip_archive:65536 cab_archive:65536 \
  inflate_diff:70000 inf_version:16384 dism_driver_table:65536 \
  postsetup_msgs:16384 agent_package_manifest:16384 content_manifest_v2:65536; do
  t="${e%%:*}"; mkdir -p "/tmp/work/$t"
  cargo fuzz run "$t" "/tmp/work/$t" "corpus/$t" -- -max_total_time=600 -max_len="${e#*:}" $L
done
```

`zip_archive` and `cab_archive` share their checks through
`fuzz_targets/common/archive_checks.rs`. `inf_version` reaches the INF
scan through the archive reader, which is the scan's only public entry.
`inflate_diff` uses `miniz_oxide` (pure Rust) as the reference inflater;
it is a dependency of this workspace only. `content_manifest_v2` uses a
test-double signature verifier.

M4 seeds are written by `examples/gen_seeds_m4.rs`
(`cargo run --example gen_seeds_m4 -- corpus`).
