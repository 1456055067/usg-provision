# Seed origin: `winapi_sd`

Every seed here is generated by our own code: self-relative security
descriptors assembled in the generator from the layout of
`specs/standards/reparse-and-security-descriptors.md` (topic 24 §7 to §9),
with example SIDs (S-1-5-18, S-1-5-32-544, S-1-5-32-545) and
access-allowed ACEs. The SIDs are test data: their meaning is not
relied on, only their SID structure (CR-RV1-002). None comes from a
WIM, a file system, a Windows installation or any product or deployment
(fuzz/README.md, seed origin rule). The whole input is the descriptor.

Regenerate (from `fuzz/`; function `sd_seeds`):

```sh
cargo run --example gen_seeds_m3 -- <scratch>
cp <scratch>/winapi_sd/*.bin corpus/winapi_sd/
```

| Seed | Content | Result |
|------|---------|--------|
| `sec004-sd-header-only.bin` | self-relative header, no parts | accepted |
| `sec004-sd-owner-group-dacl.bin` | owner, group, DACL with two ACEs | accepted |
| `sec004-sd-full.bin` | owner, group, SACL with one ACE, DACL | accepted |
| `sec004-sd-null-dacl.bin` | DACL flag with offset 0 (null DACL) | accepted, `null_dacl` |
| `sec004-sd-truncated.bin` | `sec004-sd-full` without its last 4 octets | refused, out of bounds |
| `sec004-sd-ace-past-acl.bin` | `AceCount` one more than the ACEs present | refused, ACE past the ACL |
| `sec004-sd-sid-16-subs.bin` | owner SID with 16 sub-authorities | refused, count |
| `sec004-sd-dacl-without-flag.bin` | DACL offset without the present flag | refused |
| `sec004-sd-absolute.bin` | self-relative flag clear | refused |
