# Spec traceability

Every specced requirement maps to code and a test. The first table covers
every REQ ID that milestone M1 put in scope (`specs/boot-network.md`, all
AUDITED), plus the OPEN REQs of the same spec that M1 deliberately leaves
alone. Milestone M2 requirements are in
[their own section](#m2-requirements-content-store-integrity-operator-api)
with their own evidence rules.

Evidence rules for the Status column:

- **Tested** means the test is named in the M1 QA report (2026-10-26:
  initial pass, re-verify round 1 or the final pass) and passed there.
- **Tested (in-process)** means the same, but the test runs the relay
  in-process with in-memory sockets. Live behaviour on a real network and
  real firmware is the boot smoke scenario named next to it.
- **S*n* PASS (CI 40438138720)**: the boot smoke scenario passed in
  GitHub Actions run 40438138720 (commit 70e3c1f, 2026-10-27; Linux,
  KVM, OVMF firmware, relay as uid 65534). This is live evidence from one
  lab topology, recorded from the `boot-smoke-evidence` artifact; see
  `docs/compliance/TEST_EVIDENCE.md` for what each scenario checks. It is
  added next to the in-process label and does not replace it. The
  scenarios did not run on the macOS development host, and the first CI
  run (40434148508) is superseded.
- **Documented**: an operator-facing statement in
  [`docs/operations/relay.md`](../operations/relay.md). The QA review
  result is given in each row.
- **OPEN**: the spec leaves a product question open; nothing is
  implemented beyond the AUDITED parts.

## M2 requirements (content store, integrity, operator API)

Rows cover every REQ ID of the M2 specs (`specs/os-images.md`,
`specs/os-support.md`, `specs/preinstall-env.md`,
`specs/operator-access.md`), AUDITED and OPEN, as of the uncommitted M2
work on base 55bd6a1 (2026-10-27). Where a decision settles an item the
spec still marks OPEN, the decision is cited.

M2 evidence rules for the Status column:

- **Tested (QA M2)**: the test passed in the M2 QA report's run
  (2026-10-27) on the macOS development host. API and server tests run on
  the in-memory store over real mTLS. macOS results are functional
  evidence only (POAM-2).
- **Fix-round test**: added in review fix rounds 1 or 2, after the QA
  run; passed in coders' and reviewers' local runs (macOS); QA
  re-verify pending. Not counted as Tested.
- **CI NOT RUN**: needs PostgreSQL, Linux, a Windows runner or 14 GiB of
  disk, and has not passed in CI (POAM-34). Never counted as PASS.
- **CI PASS (40601242085)**: the test passed in GitHub Actions run
  40601242085 (`workflow_dispatch`, commit d72b761 = M2 commit 5d3c8c7
  plus CI fixes, 2026-10-27; Linux, PostgreSQL 16), and where marked also
  in the push run 40601244276. Fuzz results in that run were built
  without ASan (POAM-37). Added next to the QA label; it does not replace
  it and is not a QA result. In those runs `pg-integration` failed
  (`migrate_pg::newer_schema_refused`, a stale test), so `repo_pg` and
  `e2e_pg` are still CI NOT RUN.
- **WIM CI**: `wim-samples` runs 40601244164 and 40601244679 (commit
  d72b761): the Linux `verify` job passed against DISM samples S01 to
  S07, S09, S10, S11A, S11B, S12A and S12B with the committed checker.
- **S11/S12 local**: the uncommitted S11/S12 WIM change of 2026-10-27;
  its tests passed in the coder's and reviewers' runs on macOS (R1 and
  R2 sample copies), with no QA and no CI run. Not counted as Tested.
- **DISM samples (local R1)**: `crates/usgp-image/tests/dism_samples.rs`
  passed on macOS against a local copy of `wim-samples` run R1 (GitHub
  run 40535666995). Functional evidence only; OPEN-PE-LIC is with
  counsel (POAM-35). The Linux result is WIM CI, above.
- **Deferred**: out of M2 scope by the brief or plan; no code, no test.
- **OPEN**: the spec leaves the question open; nothing is implemented
  beyond the AUDITED parts.
