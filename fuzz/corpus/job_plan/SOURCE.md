# Seed origin: `job_plan`

Every seed here is generated by our own code: a `usgp-proto`
`JobPlanV1` and `ContentManifestV1` built in the generator (the shape of
the `usgp-proto` unit-test fixtures), encoded with their own
`to_payload`, wrapped in `SignedEnvelopeV1` with 103 octets of `0x30` as
the signature (not a real signature; the target's verifiers are test
doubles), in a `ConfirmedV1` serialized with `serde_json`. The plan names
the `usgp-crypto` SHA-256 of the content manifest payload. None comes from
a server, captured traffic or any deployment of another product
(fuzz/README.md, seed origin rule).

Octet 0 selects (see `fuzz_targets/job_plan.rs`); for selector 1, octet 1
is the verifier and expectation mode.

Regenerate (from `fuzz/`; function `job_plan_seeds`):

```sh
cargo run --example gen_seeds_m3 -- corpus
```

| Seed | Selector, mode | Content |
|------|----------------|---------|
| `wu14-plan-payload.bin` | 0 | the plan payload |
| `wu14-plan-payload-steps-reversed.bin` | 0 | the plan with its steps in reverse order (refused) |
| `wu14-confirmed-all-accept-own-expectation.bin` | 1, 7 | both verifiers accept, expectation from the plan (verifies) |
| `wu14-confirmed-all-accept-fixed-expectation.bin` | 1, 3 | both accept, fixed expectation (binding refusal) |
| `wu14-confirmed-plan-refused.bin` | 1, 6 | plan verifier refuses |
| `wu14-confirmed-content-refused.bin` | 1, 5 | content verifier refuses |
| `wu14-confirmed-edition-mismatch.bin` | 1, 7 | plan names edition 2 with edition 1's name (content mismatch) |
