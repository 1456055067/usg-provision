# Seed origin: `gpt_readback`

Every seed here is generated by our own code: tables built by
`usgp_disk::GptPlan::new` and laid out from `GptPlan::writes`, with
partition GUIDs from a fixed linear congruential sequence in the
generator, plus one legacy MBR record written in the generator from the
MBR layout of `specs/standards/gpt.md` §3. None comes from a real disk, a
disk image, a firmware dump or any deployment of another product
(fuzz/README.md, seed origin rule).

Framing: selector octet, total LBAs (u32 LE), head length (u16 LE), head
(written at LBA 0), tail (written to end at the last LBA); see
`fuzz_targets/gpt_readback.rs`. Head and tail of a plan are its writes
below and above the middle of the disk.

Regenerate (from `fuzz/`; function `gpt_seeds`):

```sh
cargo run --example gen_seeds_m3 -- corpus
```

| Seed | Content |
|------|---------|
| `wu14-gpt-512-two-parts.bin` | 512-byte sectors, 4096 LBAs, ESP 34-2081 and basic data 2082-4062, both copies (accepted) |
| `wu14-gpt-512-two-parts-limits-128.bin` | the same table under the 128 x 128-byte limits (accepted) |
| `wu14-gpt-512-two-parts-limits-4.bin` | the same table under the 4-entry limits (refused, `Limit`) |
| `wu14-gpt-512-empty.bin` | 512-byte sectors, 4096 LBAs, no partitions (accepted) |
| `wu14-gpt-512-no-backup.bin` | the two-partition head without its tail (backup header missing; refused) |
| `wu14-gpt-4096-one-part.bin` | 4096-byte sectors, 512 LBAs, one basic data partition 6-506 (accepted) |
| `wu14-gpt-1024-sectors.bin` | the 512-byte table on a 1024-byte-sector disk (refused, unsupported sector size) |
| `wu14-gpt-legacy-mbr.bin` | LBA 0 with one legacy record (type `0x07`, LBA 2048, 2048 LBAs) and the `0xAA55` signature (refused, legacy MBR) |
