# Seed origin: `wim_check`

Every seed here is generated by our own code: the `usgp-image` test WIM
builder (`WimBuilder`, feature `testkit`) and, for the XML-only seeds,
`usgp_image::wim::xml::encode_utf16` of text written in the generator. None
comes from a third-party WIM file or tool, from Windows media, from a
packet capture or log, or from any deployment of another product
(fuzz/README.md, seed origin rule; decision 0006 item 4). The DISM-made R1
samples are **not** used as seeds.

Each seed is a whole WIM file as the builder writes it. `wu9-*` images
carry one 12-byte file each (`small` in the generator) to keep the files
small; the check reads metadata, not file content.

Regenerate (from the repository root):

```sh
cargo run -p usgp-image --features testkit --example gen_fuzz_seeds -- <scratch>
cp <scratch>/wim_check/*.bin fuzz/corpus/wim_check/
(cd fuzz && cargo run --example gen_seeds -- corpus)
```

The crate example also writes `<scratch>/xpress_chunk/`; those files are
**not** copied, because the `xpress_chunk` target expects a framing
prefix (see `fuzz/corpus/xpress_chunk/SOURCE.md`).

| `none-1.bin` | `crates/usgp-image/examples/gen_fuzz_seeds.rs` | uncompressed, one image (`a`, `b`), default files |

| `xpress-3-integrity-boot.bin` | same | XPRESS, three images, integrity table, boot index 2 |

| `wu9-none-integrity.bin` | same | uncompressed, one image, integrity table |
| `wu9-xpress-no-description.bin` | same | XPRESS, one image with no `DESCRIPTION` |
| `wu9-xpress-bad-metadata-hash.bin` | same | XPRESS, two images, wrong SHA-1 on image 2 metadata (refused) |
| `wu9-xpress-identical-metadata.bin` | same | XPRESS, two images with identical files and identical metadata (one SHA-1, two ranges; accepted, BOOT-011) |
| `wu9-xpress-reused-metadata.bin` | same | XPRESS, two images naming one metadata resource through equal lookup entries (the S11 layout; accepted, OBS-018) |

| `wu9-split-part.bin` | same | part 1 of 2 (refused as split) |
| `wu9-xml-doctype.bin` | same | XML replaced by a document with a DOCTYPE (refused) |
