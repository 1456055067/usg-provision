| POAM-15 | TFTP verification has no time bound of its own (boot review finding BOOT-012, residual). For every RRQ the relay reads and hashes the whole file again, with no cache. That read, the wait for one of `limits.verify_concurrency` permits (default 2), and OACK to ACK 0 all share one deadline: `tftp.handshake_timeout_ms` (default 2000 ms) from RRQ arrival. Nothing at load time relates `tftp.max_file_size_bytes` (up to 4 GiB) or the largest manifest entry to that deadline. **Effect (a):** a published file whose read and hash take longer than the deadline on the host's storage is never served. Every RRQ for it is dropped without a TFTP ERROR, including client retransmissions and the tsize probe. The relay stays `running`. This fails closed: wrong bytes are never served. **Effect (b):** a cancelled read keeps its permit until the read ends, and its result is thrown away. One client retrying an over-limit file can therefore keep the permits busy, and requests for other files can then queue past their own deadlines. This is the reliability cost of the bound on concurrent reads. **Detection:** `boot.file.verify_slow` (outcome `dropped`, with file, size, elapsed_ms, limit_ms, suppressed_since_last), at most once per file per 60 s, plus the `tftp_verify_timeout` shed counter. Limits of detection: `elapsed_ms` is measured at the deadline, so it is always about `limit_ms`. The event cannot tell a slow file from one queued behind other reads, and does not record the real read time. Suppressed timeouts are reported only when a later event fires. **Compensating factors:** fails closed (SI-7 kept), audited by file name (AU-2), concurrent reads bounded (SC-5). **Planned remediation:** a configurable verification timeout, checked at load and by `--check-config` against the largest manifest entry; total pending lifetime documented as verification timeout plus handshake timeout, with the TFTP slot arithmetic redone; real read time in the event; a boot smoke variant with a file slower than the bound. | SC-5, SI-7 (REQ-BOOT-034, REQ-BOOT-044) | [`services/usgp-relay/src/tftp.rs`](../../services/usgp-relay/src/tftp.rs) (verification deadline), [`services/usgp-relay/src/content.rs`](../../services/usgp-relay/src/content.rs) (verification and `boot.file.verify_slow`); no `// POAM:` marker in code | Later milestone (config change) | Open — risk accepted by owner 2026-10-26 |
